# Списки, пошук, фільтри й порожній результат

Читай цей файл **лише** якщо в наданому тексті вже є список/каталог/таблиця, пошук, фільтр, сортування, пагінація або заявлений порожній результат.

Це не 8-й критерій. Ті самі 7 критеріїв і та сама заборона вигадувати поведінку.

Не відкривай цей файл «про всяк випадок». Немає списку, пошуку, фільтра чи empty — не став питань про пагінацію, debounce чи нечіткий пошук.

Ролі, статуси й AS-IS/TO-BE — не ця лінза. Див. [actors-states-and-delta.md](actors-states-and-delta.md).

Числа, тексти повідомлень, строки й відправки — не ця лінза, якщо вони не описують саме список. Див. [values-messages-and-effects.md](values-messages-and-effects.md).

---

## Коли відкривати розділ

| У тексті є | Відкрий |
|---|---|
| список, каталог, таблиця, історія замовлень, «показує перелік» | Списки |
| пошук, search, знайти, рядок пошуку | Пошук |
| фільтр, filter by, «лише зі статусом» | Фільтри |
| сортування, sort by, «відсортовано» | Сортування |
| сторінка, пагінація, «по N на сторінці», infinite scroll | Пагінація |
| порожній список, empty, «якщо нічого не знайдено» | Порожній результат |

Можна відкрити кілька розділів. Одна проблема — один рядок у таблиці.

## Списки

Застосовуй існуючі критерії, якщо текст **уже заявляє** перелік записів.

«Користувач бачить список своїх замовлень» саме по собі — не діра. Не вимагай колонок, якщо текст їх не обіцяє.

| Ситуація | Оцінка |
|---|---|
| Список заявлений, є хоча б один спостережуваний слід (названі поля або явна дія над рядком) | Не `Fail` |
| «Користувач бачить зручний каталог» як єдина норма | Повнота / Тестованість за загальними правилами |
| Названі поля рядка суперечать одне одному в story і AC | Несуперечність |

Не став Critical/Major за те, що не описані:

- пагінація, infinite scroll, віртуалізація;
- сортування за замовчуванням;
- порожній стан, якщо текст його не обіцяє;
- ширина колонок, sticky header, адаптив.

Зразок готового списку: [../examples/order-list-ready.md](../examples/order-list-ready.md).

## Пошук

Застосовуй існуючі критерії, якщо текст **уже заявляє** пошук.

Для заявленого пошуку як окремої поведінки має бути видно:

- за чим шукати (поле, номер, назва) **або** явний результат, який можна відрізнити від «просто список»;
- що вважати успіхом (список звужується / є збіги).

| Ситуація | Оцінка |
|---|---|
| AC обіцяє «користувач може шукати», немає поля і немає результату | Повнота. Якщо основний список уже тестований — Major, не Critical |
| Пошук за номером замовлення, список показує лише збіги | Не `Fail`. Не вигадуй fuzzy, debounce, «від 3 символів» |
| Пошук — єдина нова обіцянка без поля і без результату | Повнота, зазвичай Critical |

Не став Critical/Major за те, що не описані:

- нечіткий пошук, трансліт, опечатки;
- debounce, мінімум символів, підсвітка збігів;
- історія запитів, автодоповнення;
- окремий backend-індекс.

Зразок Major: [../examples/search-needs-field.md](../examples/search-needs-field.md).

## Фільтри

Застосовуй існуючі критерії, якщо текст **уже заявляє** фільтр.

| Ситуація | Оцінка |
|---|---|
| «Користувач може фільтрувати замовлення» без «за чим» і без видимого результату | Повнота. Важливий уже заявлений шлях — Major |
| Фільтр за названими статусами, список показує лише вибране | Не `Fail`. Не вигадуй мультиселект, URL, діапазон дат |
| Story обіцяє фільтр, AC або out of scope його забороняє | Несуперечність |

Не став Critical/Major за те, що не описані:

- комбінація кількох фільтрів, якщо комбінація не заявлена;
- скидання фільтра, якщо текст його не обіцяє;
- збереження фільтра після перезавантаження;
- query-параметри в адресі.

## Сортування

Застосовуй існуючі критерії, якщо текст **уже заявляє** сортування.

| Ситуація | Оцінка |
|---|---|
| «Користувач може сортувати» без поля — і це основна нова поведінка | Повнота, зазвичай Major |
| «Відсортовано за датою» без напрямку, але список і фільтр уже тестовані | Не `Fail`. Необов'язкове питання, не Major |
| AC-1 «завжди за назвою», AC-2 «користувач сортує за ціною» як одночасні норми без пояснення | Несуперечність |

Не став Critical/Major за те, що не описані:

- напрямок ASC/DESC, якщо сортування не є єдиною новою нормою;
- вторинний ключ сортування;
- збереження вибору після оновлення сторінки.

## Пагінація

Застосовуй існуючі критерії, якщо текст **уже називає** сторінку або розмір сторінки.

| Ситуація | Оцінка |
|---|---|
| Два різні розміри сторінки для того самого списку (20 і 50) | Несуперечність, Critical |
| «По 20 на сторінці» і кнопка «Далі» показує наступні 20 | Не `Fail`. Не вигадуй infinite scroll |
| Список без слова «сторінка» | Не `Fail`. Не вимагай пагінації |

Не став Critical/Major за те, що не описані:

- остання неповна сторінка;
- глибокі лінки на сторінку N;
- зміна page size користувачем, якщо текст її не обіцяє.

Зразок Critical: [../examples/page-size-contradiction.md](../examples/page-size-contradiction.md).

## Порожній результат

Застосовуй існуючі критерії, якщо текст **уже обіцяє** порожній список або empty state.

Порожній список сам по собі спостережуваний. Відсутність окремої копії — не діра, якщо текст не обіцяє повідомлення.

| Ситуація | Оцінка |
|---|---|
| «Якщо нічого не знайдено — показуємо повідомлення» без тексту, і це **єдина** реакція на порожній пошук/фільтр | Повнота / Тестованість. Якщо успішний список уже є — Minor або необов'язкове питання |
| Конкретний текст «Замовлень не знайдено» | Не `Fail`. Не вимагай ілюстрацію, CTA, окремий екран |
| Empty не згаданий | Не `Fail`. Не вигадуй empty state |

Не став Critical/Major за те, що не описані:

- ілюстрація, кнопка «Скинути фільтр», окремий лендінг;
- різниця «немає замовлень узагалі» vs «фільтр нічого не дав», якщо текст її не обіцяє;
- i18n тексту empty.

## Як записувати

1. Звичайний критерій: найчастіше Повнота (немає поля/результату пошуку чи фільтра) або Несуперечність (різний page size).
2. Не пиши в таблиці «домен: список» / «домен: пошук».
3. Не дублюй ту саму прогалину окремим рядком «немає debounce».
4. Незаявлена пагінація, fuzzy, URL, empty-ілюстрація — лише необов'язкове питання, ніколи Critical/Major.
5. Коротка цитата обов'язкова.
6. У готові факти клади лише названі поля рядка, фільтр, поле пошуку, розмір сторінки й текст empty. Не клади вигадану пагінацію.

У розкладі AC:

- заявлений пошук/фільтр без поля й результату → `блокує`;
- два розміри сторінки → відповідні AC `блокує`;
- другорядна копія empty → `другорядний TBD`, якщо основний список від цього не залежить.
