# Ролі, статуси й зміна (delta)

Читай цей файл **лише** якщо в наданому тексті вже є ролі/права, статуси/переходи або маркери зміни (AS-IS / TO-BE / «змінити» / «тепер»).

Це не 8-й критерій. Ті самі 7 критеріїв і та сама заборона вигадувати поведінку.

Не відкривай цей файл «про всяк випадок». Немає названих ролей, статусів і зміни — не став питань про RBAC, state machine чи поточний прод.

Числа, тексти повідомлень, строки й відправки — не цей файл. Див. [values-messages-and-effects.md](values-messages-and-effects.md).

Списки, пошук, фільтри, пагінація й empty — не цей файл. Див. [lists-search-and-empty.md](lists-search-and-empty.md).

## Коли відкривати розділ

| У тексті є | Відкрий |
|---|---|
| роль, права, гість, адмін, менеджер, покупець і продавець в одній вимозі, «тільки X може» | Ролі |
| статус, стан, перевести, «зі статусу», «після цього статус =» | Статуси |
| AS-IS, TO-BE, було/стало, змінити, замість, тепер, раніше, «замість N тепер M» | Зміна (delta) |

Можна відкрити кілька розділів. Одна проблема — один рядок у таблиці.

## Ролі

Застосовуй існуючі критерії, якщо текст **уже називає** кілька ролей і **обіцяє** різну поведінку.

| Ситуація | Оцінка |
|---|---|
| Дві ролі заявлені, у однієї немає expected result | Повнота. Якщо це важливий уже заявлений шлях — Major |
| «Адмін може скасувати замовлення» і все | Не `Fail`. Не вигадуй, що бачить інша роль |
| Story обіцяє гостя й логін, AC описує лише логін | Повнота для заявленого гостя, не вигадуй екран 403 |
| Одна роль, кілька AC тієї самої дії | Не атомарність і не «діра в правах» |

Не став Critical/Major за те, що не описані:

- повна матриця RBAC;
- приховані ролі (супер-адмін, підтримка);
- сторінка 403 / «немає доступу», якщо текст її не обіцяє;
- аудит, impersonation, делегування.

Зразок Major: [../examples/role-split-needs-clarification.md](../examples/role-split-needs-clarification.md).

## Статуси

Застосовуй існуючі критерії, якщо текст **уже називає** статуси й **заявляє** перехід.

Для заявленого переходу має бути видно:

- звідки (конкретний статус або явна фраза на кшталт «з Нове або Оплачено»);
- що запускає перехід;
- видимий результат (новий статус і/або повідомлення / запис).

| Ситуація | Оцінка |
|---|---|
| Перехід заявлений, немає «звідки» або немає результату | Повнота |
| AC-1: скасування з «Нове»; AC-2: «скасування завжди доступне» | Несуперечність |
| «Користувач може скасувати замовлення» без жодного статусу | Не `Fail`. Не вигадуй state machine |

Не став Critical/Major за те, що не описані:

- повний граф статусів продукту;
- проміжні технічні статуси;
- таймери автопереходу;
- хто ще може зробити той самий перехід;
- сусідні флоу (оплата, refund), якщо їх немає в тексті.

Явне «поза скоупом: скасування оплачених» — сила, не діра.

Зразок готової вимоги: [../examples/status-transition-ready.md](../examples/status-transition-ready.md).

## Зміна (delta)

Якщо тікет описує зміну вже існуючої поведінки — джерело правди для рев'ю є **TO-BE** (нове правило).

Не вигадуй поточний прод, історію релізу чи міграцію даних.

| Ситуація | Оцінка |
|---|---|
| Story: «ліміт тепер 20», AC досі «від 1 до 10 включно» | Несуперечність, Critical |
| «Тепер гість може застосувати промокод», немає нового результату | Повнота |
| AS-IS і TO-BE обидва дані, TO-BE конкретне | Рев'ю TO-BE. Різниця AS-IS ≠ TO-BE — це зміна, не суперечність |
| Зміна межі 10 → 20 описана в story і в AC однаково | ✅ Не вимагай міграції старих кошиків |

Не став Critical/Major за те, що не описані:

- поведінка вже збережених даних / старих кошиків;
- регресія сусідніх фіч;
- feature flag, відсоток розгортання;
- «що було в проді минулого спринту», якщо AS-IS не вставлено.

Не ходи в історію продукту. Не підставляй «очевидний» AS-IS.

Зразок Critical: [../examples/delta-ac-contradiction.md](../examples/delta-ac-contradiction.md).

## Як записувати

1. Звичайний критерій: найчастіше Повнота, Однозначність або Несуперечність.
2. Не пиши в таблиці «домен: ролі» / «домен: статуси».
3. Не дублюй ту саму прогалину окремим рядком «немає RBAC».
4. Незаявлена матриця прав, повний граф статусів, міграція — лише необов'язкове питання, ніколи Critical/Major.
5. Коротка цитата обов'язкова.
6. У готові факти клади лише названі ролі, названі переходи й TO-BE. Не клади вигаданий AS-IS.

У розкладі AC:

- роль/перехід без результату → `блокує`;
- зміна, яка суперечить AC → відповідні AC `блокує`;
- другорядна копія для іншої ролі → `другорядний TBD`, якщо основний шлях від цього не залежить.
