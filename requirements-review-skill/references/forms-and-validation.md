# Форми, поля й валідація

Читай цей файл **лише** якщо в наданому тексті вже є форма, поле вводу, валідація, обов'язкове поле, маска або збереження/submit форми.

Це не 8-й критерій. Ті самі 7 критеріїв і та сама заборона вигадувати поведінку.

Не відкривай цей файл «про всяк випадок». Немає форми чи валідації — не став питань про порожнє поле, `5.0`, onBlur, маску чи тип інпута.

Числа й точні тексти помилок — не ця лінза, якщо вони не описують саме поле форми. Див. [values-messages-and-effects.md](values-messages-and-effects.md).

Списки й пошук — не ця лінза. Див. [lists-search-and-empty.md](lists-search-and-empty.md).

Оплата й refund — не ця лінза, навіть якщо є кнопка «Оплатити». Див. [payments-and-charges.md](payments-and-charges.md).

## Коли відкривати розділ

| У тексті є | Відкрий |
|---|---|
| форма, профіль, «поле …», input, «заповнює» | Поля |
| валідація, «обов'язкове», required, «невалідне» | Валідація |
| «Зберегти», submit, «не зберігає», успішне збереження | Збереження |
| маска, формат поля, «вигляд name@domain» | Формат |
| порожнє поле, trim, blur, тип інпута, HTML5 | Лише щоб **не** вигадати їх як дефект |

Можна відкрити кілька розділів. Одна проблема — один рядок у таблиці.

## Поля

Застосовуй існуючі критерії, якщо текст **уже заявляє** форму або назване поле.

Назване поле — сила. Не вимагай повного складу форми, якщо текст називає лише одне поле.

| Ситуація | Оцінка |
|---|---|
| Є поле, межі або формат і видима реакція | Не `Fail`. Не вигадуй інші поля форми |
| «Користувач заповнює зручну форму» як єдина норма | Повнота / Тестованість за загальними правилами |
| Story називає поле «Email», AC говорить про «Телефон» як те саме єдине поле | Несуперечність |

Не став Critical/Major за те, що не описані:

- сусідні поля, яких немає в тексті;
- підказка, placeholder, іконка, ширина інпута;
- тип UI-контролу (input, select, textarea, stepper);
- порядок табів, автофокус.

Зразок готової валідації поля: [../examples/quantity-field-review.md](../examples/quantity-field-review.md).

Зразок готової форми зі збереженням: [../examples/profile-form-ready.md](../examples/profile-form-ready.md).

## Валідація

Застосовуй існуючі критерії, якщо текст **уже заявляє** валідацію або обов'язковість.

Для заявленої обов'язковості як окремої поведінки має бути видно, що саме станеться, якщо поле порожнє (повідомлення і/або «не зберігає»).

Порожнє поле **не** є дірою, якщо текст його не обіцяє як правило, а межі й реакція на невалід уже задані. Це калібрування кількості 1–10.

| Ситуація | Оцінка |
|---|---|
| «Поле Email обов'язкове, система коректно валідує форму» без видимого результату для порожнього | Повнота. Якщо збереження вже тестоване — Major, не Critical |
| Обов'язковість — єдина нова обіцянка без будь-якого результату | Повнота, зазвичай Critical |
| Порожнє → «Вкажіть email», профіль не зберігається | Не `Fail`. Не вигадуй trim, onBlur, live-валідацію |
| AC-1: поле обов'язкове; AC-2: можна зберегти без цього поля | Несуперечність, Critical |
| Межі 1–10 і негатив із конкретним текстом уже є; порожнє не згадане | Не `Fail`. Необов'язкове питання, як у кількості |

Не став Critical/Major за те, що не описані:

- порожнє поле, пробіли, trim, copy-paste — якщо обов'язковість не заявлена;
- формат `5.0` / `01`, локаль числа;
- момент валідації (input / blur / submit), якщо дія «Зберегти» вже названа або негатив уже видимий;
- окрема backend/API-валідація;
- HTML5 vs власна перевірка, ARIA, скрінрідер.

Зразок Major: [../examples/required-field-needs-result.md](../examples/required-field-needs-result.md).

Зразок Critical: [../examples/required-vs-optional-contradiction.md](../examples/required-vs-optional-contradiction.md).

## Збереження

Застосовуй існуючі критерії, якщо текст **уже заявляє** збереження або submit форми.

| Ситуація | Оцінка |
|---|---|
| «Користувач зберігає профіль» без видимого успіху, і це вже заявлена дія | Повнота. Якщо валідація поля вже тестована — Major |
| Збереження — єдина нова обіцянка без результату | Повнота, зазвичай Critical |
| Після «Зберегти» показується «Профіль збережено»; невалід не зберігає | Не `Fail`. Не вигадуй тост vs інлайн, чернетку, автосейв |
| Story обіцяє збереження, AC або out of scope його забороняє | Несуперечність |

Не став Critical/Major за те, що не описані:

- автосейв, чернетка, «залишити сторінку без збереження»;
- повторний клік «Зберегти», подвійний submit;
- який саме запис оновлюється на бекенді.

## Формат

Застосовуй існуючі критерії, якщо текст **уже називає** маску або формат поля.

| Ситуація | Оцінка |
|---|---|
| «Email має вигляд name@domain» + видимий успіх/помилка | Не `Fail`. Не вимагай RFC, IDN, список доменів |
| «Поле з маскою» без зразка, і маска — основна нова норма | Повнота, зазвичай Major |
| AC-1 маска `+38 (___) ___-__-__`, AC-2 те саме поле без маски як одночасна норма | Несуперечність |
| Формат не названий, але межі або обов'язковість уже конкретні | Не `Fail`. Не вигадуй маску |

Не став Critical/Major за те, що не описані:

- повний RFC для email, міжнародні номери, лідируючі нулі;
- окрема маска vs вільний ввід, якщо текст називає лише вигляд прикладу;
- автопідстановка `@`, країна телефону.

## Як записувати

1. Звичайний критерій: найчастіше Повнота (заявлена обов'язковість/валідація/збереження без видимого результату) або Несуперечність (обов'язкове vs необов'язкове для того самого поля).
2. Не пиши в таблиці «домен: форма» / «домен: HTML5».
3. Не дублюй ту саму прогалину окремим рядком «немає onBlur» або «немає backend-валідації».
4. Незаявлені порожнє поле, `5.0`, trim, blur/submit, тип інпута, маска, ARIA — лише необов'язкове питання, ніколи Critical/Major.
5. Коротка цитата обов'язкова.
6. У готові факти клади лише названі поля, заявлену обов'язковість із видимим результатом, правило валідації, текст помилки, успіх збереження. Не клади вигаданий onBlur чи тип контролу.

У розкладі AC:

- заявлена обов'язковість / валідація / збереження без видимого результату → `блокує`;
- обов'язкове vs необов'язкове для того самого поля → відповідні AC `блокує`;
- другорядна копія підказки / тосту → `другорядний TBD`, якщо основний шлях від цього не залежить.
